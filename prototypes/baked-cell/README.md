# 試作 08: 単細胞の「焼きカード」

## 確かめる問い

図鑑カードの密度は、スマホ側で描かず GitHub Actions 側で画像に焼く（bake）ことで上げられるか。

## 動かし方

```text
node prototypes/baked-cell/bake.mjs [出力先] [--size 360] [--quality 0.9] [--limit N] [--id 1713]
python3 -m http.server 8000   # リポジトリのルートで
# http://localhost:8000/prototypes/baked-cell/compare.html
```

依存は playwright だけ（`verify.yml` がすでに入れている）。Chromium の canvas で
そのまま WebP に符号化するので、ImageMagick も sharp も要らない。
本番の `engine/`、`viewer/plan.mjs`、`viewer/palette.mjs` を読むだけで、書き換えない。

## 作ったもの

- `viewer/plan.mjs` に `cellPlan()` を足した。描き方を知らない語彙だけを持つ:
  `membranes`（入れ子の膜）、`nucleus`（核と帯の本数）、`organelles`（液胞・顆粒・コイル）、
  `cilia`（繊毛）、`pseudopods`（偽足）、`stripes`（構造としての しま）。
  形質の解釈はすべてここにあり、描く側（`cell-svg.mjs`）には持ち込んでいない。
  **`bodyPlan()` は変えていない。図鑑カード48枚の SVG がバイト単位で前と同一であることを確認した。**
- `cell-svg.mjs`: 高密度な静止画の SVG。焼く前提なので、スマホでは重くて使えない手を使っている
  （`feTurbulence` + `feDisplacementMap` で膜の粒とゆがみ、`feGaussianBlur` で屈折のにじみと
  ピント外のぼけ）。これが「焼くと何が得か」の中身。
- `bake.mjs`: Actions でも動く焼き。`compare.html`: 並べて見る比較ページ。
- `sample/cell-1713.webp`: 比較ページ用に対象1枚だけ置いてある（残りは `bake.mjs` で作る）。

## 実測

すべてこのコンテナ（Chromium、ソフトウェア描画）での値。実機のスマホは未確認。

### 焼きのコスト

40系統（いま生きている単細胞すべて）を 360x360・品質0.9 で焼いた。

| | |
|---|---|
| 1枚あたりの大きさ | **11.4KB**（中央値。最小 9.1、最大 12.8。対象 id1713 は 12.7KB） |
| 1枚あたりの時間 | **34ms**（中央値） |
| 40枚の合計 | 1.5秒 / 454.9KB |
| 48枚に換算 | **1.6秒 / 548KB** |

大きさと品質を振った場合（各8枚）:

| 出力 | 品質 | 1枚 | 1枚の大きさ |
|---|---|---|---|
| 240x240 | 0.75 | 19ms | 4.6KB |
| 240x240 | 0.90 | 24ms | 6.7KB |
| 360x360 | 0.75 | 39ms | 7.4KB |
| 360x360 | 0.90 | 41ms | 11.5KB |

360x360 はカード表示（スマホ幅2列で約174px）の約2倍。Retina 想定の基準として選んだ。

### 運用に耐えるか

- **焼きは決定論的**。同じ系統を2回焼くとバイト単位で同じ画像になった（6枚で確認）。
  つまり、変わっていない系統は git が書き換えを記録しない。
- **1日あたり焼き直す枚数は、いまのところ 0枚**。#265→#267、#267→#269、#269→#271、
  #271→#273 の4日ぶんで、生きている単細胞40系統の顔ぶれは1つも変わらなかった。
  形の時代は1号200万年しか進まないので、日ごとの入れ替わりがほとんどない。
- 最悪の場合（大量絶滅などで48系統すべてが入れ替わる）でも 1.6秒 / 548KB。
  毎日2回の実行の中では誤差（いまの `daily.sh` は `npm test` だけで約26秒かかる）。

→ 判定基準2（48体・1日2回の運用に耐えるか）は**耐える**。むしろ余裕がある。

### スマホ側の表示コスト

同じスマホ幅（390px、画素密度2）で、48枚並べた状態を比べた。

| | いまの図鑑（SVG） | 焼きカード（WebP） |
|---|---|---|
| DOM の節点 | 2,883（うち SVG 2,555） | **219** |
| 初回描画 | **24ms** | 36ms |
| load | 55ms | **47ms** |
| スクロール中のフレーム | 16.7ms（60fps） | 16.7ms（60fps、最大22.3ms） |
| 転送量 | SVG 207KB（HTML に埋まる） | 画像 約548KB（遅延読み込みあり） |

**正直に書くと、焼いても速くはならない。** いまの SVG もすでに60fpsで、初回描画はむしろ
SVG のほうが速い（画像の復号が要らないため）。DOM の節点は13分の1になるが、この規模では
体感差にならない。

焼いて得られるのは速さではなく**密度**。`feTurbulence` や多層のぼかしを48枚ぶんスマホで
毎フレーム動かすのは現実的でないが、焼けば1枚の画像として置くだけで済む。
この試作の価値はそこにある、というのが実測から言えること。

## 目標コンセプト画との比較（2026-11-24 受領）

目標画は Owner から受け取った1枚（顕微鏡で覗いた細胞。紫と青緑の2色、濡れた質感、
分岐する偽足、密な繊毛、多数の細胞小器官、ピント外の土）。**リポジトリには置いていない**
（公開範囲は Owner が決めるため）。比較は受領した画と `sample/cell-1713.webp` を
同じ大きさに並べて行った。

### 判定の前提（Owner 決定、2026-11-24）

- 偽足0本（`asym` が単細胞に出ない）と、縦の占有率約55%（重力1.48倍で平たい）は
  形質の帰結なので未達に数えない。7割の判定は「形質に阻まれていない要素」の中で行う。

### 要素ごと

| 観点 | 目標画 | 焼きカード | 到達 |
|---|---|---|---|
| 膜の半透明と層 | 膜そのものが太い帯で、縞が帯の上を走る。奥に同心の境界が2〜3本見え、向こう側が透ける | 細い輪郭が3本。膜に厚みがなく、内側は平らな塗り | **3割** |
| 核の大きさと縞の構造感 | 球に縞が巻きつき、縁へ行くほど詰まる。球としての陰影が強い | 大きさはほぼ同じ。縞は水平の帯を楕円で切っただけで、球に巻きついていない | **5割** |
| 内部器官の見え方 | 25個ほど。ミトコンドリアには内部のひだ、小胞には鏡面のハイライト。紫の地に青緑で強い対比 | 5個。地の色と同系で対比が弱く、コイルはほぼ見えない | **3割** |
| 繊毛 | 長く細い毛が密に、長さがばらつき、先が光を拾う | 54本あるが短く均一で、光を拾わない。毛というより起毛 | **5割** |
| 光とにじみ | 全体に鏡面のハイライト。器官が発光し、膜を光が透過する | 輪郭の屈折のにじみ1本だけ。内側に鏡面も発光もない | **4割** |
| 背景のピント外ぼけ | 土と礫が暖色で奥行きを作り、下に接地面がある | ほぼ黒に薄い点が9個。空っぽ | **2割** |
| 全体の色の深さ | 紫と青緑の2色で、黒から白まで明度の幅が広い | 青灰1色で明度が中間に寄り、全体に褪せている | **3割** |

**7割には届いていない。形質に阻まれていない7観点の平均で、およそ3.5割。**

### 差分の分類

**実装で埋められるもの**（この試作の作り方を変えずに、描き足せば届く）

- 膜を「線」ではなく「帯」にする。外側の輪郭と内側の輪郭の間を塗り、縞をその帯の上に走らせる。
  いちばん効く差分がこれ。目標画の印象の大半は太い縞の帯から来ている
- 核の縞を円弧にして球に巻きつけ、縁へ行くほど間隔を詰める
- 器官を5個から20個台に増やし、アクセント色（`palette.accent`）で地と対比させ、
  ミトコンドリアには内部のひだを描く
- 繊毛を長く細くし、本数と長さをばらつかせ、先を明るくする
- 背景のぼけを増やし、大きさと色をばらつかせ、下に接地面を置く
- 明度の幅を広げる。いまは中間に寄りすぎている

**目標画側の盛りすぎ**（追うべきでないもの）

- 濡れた質感と全面の鏡面ハイライト。`docs/art-bible.md` 9「避けるもの: 写実的な質感」に
  正面から反する。Muse も「濡れた質感に寄せると『キモいだけ』に転ぶ」と警告していた。
  追うなら柱とアートバイブルを先に変える話になる
- 紫と青緑の2色そのもの。色は恒星の種類が決める（アートバイブル4）。この惑星は青白い恒星
  なので寒色になる。黄色い恒星や赤色矮星の惑星なら目標画に近い色になりうるが、
  この個体で目標画の色を出すのは決まりに反する。明度の幅と、アクセント色の使い方は
  決まりの中で広げられる
- 分岐する大きな偽足。形質（`asym`）の帰結として扱う（上の前提）

要するに、**足りないぶんのほとんどは普通の描き足しで埋まり、埋めてはいけないのは
写実の質感と色そのものだけ**。今回は実装を変えていない。

## 分かった不都合

**いまの決まりでは、単細胞に `asym` は出ない。** 段階1で、左右の非対称と関節の向きの変異を
「体の型ができてから（複雑さ3以上）」に限定したため。条件に合う29系統すべてが `asym: 0` で、
偽足は構造的に生えない。

形質の決まり方は触らない指示なので、実装は仕様どおり `asym` から出すままにしてある。
これは段階2（収斂）が扱う領域への申し送り。単細胞にも形の個性を持たせたいなら、
`lookQuirkChance` の適用条件を見直すことになる。

## 状態

判定待ち（2026-11-24）。判定基準は2つ。

1. 見た目が、目標コンセプト画の印象の7割に届くか → **届いていない（およそ3.5割）**。
   不足のほとんどは実装で埋められる（上の分類）。
2. 1枚あたりのファイルサイズと生成時間が、48体・1日2回の運用に耐えるか → **耐える**。
   1枚 11.4KB / 34ms、48枚で 1.6秒 / 548KB。焼きは決定論的で、変わらない系統は焼き直さない。

仮説そのもの（密度を上げる手段として焼きが使えるか）は、2が通ったことで成立している。
1が届かないのは焼きの限界ではなく、描き足しの量の問題。次にどこまで描き足すかは Owner の判断。
