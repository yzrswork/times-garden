# 試作 08: 単細胞の「焼きカード」（v3）

## 確かめる問い

図鑑カードの密度は、スマホ側で描かず GitHub Actions 側で画像に焼く（bake）ことで上げられるか。

## 動かし方

```text
node prototypes/baked-cell/bake.mjs [出力先] [--size 360] [--quality 0.9] [--limit N] [--id 1713]
node prototypes/baked-cell/contact.mjs [焼いた画像の置き場] [出力先]   # コンタクトシート
python3 -m http.server 8000   # リポジトリのルートで
# http://localhost:8000/prototypes/baked-cell/compare.html
```

依存は playwright だけ（`verify.yml` がすでに入れている）。Chromium の canvas で
そのまま WebP に符号化するので、ImageMagick も sharp も要らない。
本番の `engine/`、`viewer/plan.mjs`、`viewer/palette.mjs` を読むだけで、書き換えない。

## 対象

| | |
|---|---|
| id | **1713**（#189 に分かれた） |
| 形質 | `form: blob` / `pattern: stripes`（しま） / `eyeKind: none` / `cover: bare` / `limb: none` / `depth: shallow` / `asym: 0` / `joint: 0` / `drift: -4` |
| 複雑さ | 2（真核の生き物） |
| 大きさ | 0.0000438 m（43.8µm）＝「目に見えない」 |
| 場所 | 海の浅いところ |
| 惑星 | 青白い恒星 / 重力 1.48倍 / 大気 1.58倍 |

条件（しま・目に見えない）に合う系統は29あり、そのうち id が最小のものを選んだ。
29系統すべて `asym: 0` だった（下記「分かった不都合」）。

## 作ったもの

- `viewer/plan.mjs` に `cellPlan()` を足した。描き方を知らない語彙だけを持つ:
  `membranes`（入れ子の膜）、`nucleus`（核と帯の本数）、`organelles`（液胞・顆粒・コイル）、
  `cilia`（繊毛）、`pseudopods`（偽足）、`stripes`（構造としての しま）。
  形質の解釈はすべてここにあり、描く側（`cell-svg.mjs`）には持ち込んでいない。
  **`bodyPlan()` は変えていない。図鑑カード48枚の SVG がバイト単位で前と同一であることを確認した。**
- `cell-svg.mjs`: 高密度な静止画の SVG。焼く前提なので、スマホでは重くて使えない手を使っている
  （`feTurbulence` + `feDisplacementMap` で膜の粒とゆがみ、`feGaussianBlur` で屈折のにじみと
  ピント外のぼけ）。これが「焼くと何が得か」の中身。
- `bake.mjs`: Actions でも動く焼き。`compare.html`: 並べて見る比較ページ。
- `sample/cell-1713.webp`: 比較ページ用に対象1枚だけ置いてある（残りは `bake.mjs` で作る）。

## 実測

すべてこのコンテナ（Chromium、ソフトウェア描画）での値。実機のスマホは未確認。

### 焼きのコスト（v2）

40系統（いま生きている単細胞すべて）を 360x360・品質0.9 で焼いた。括弧内は v1 の値。

| | |
|---|---|
| 1枚あたりの大きさ | **29.9KB**（v1 11.4KB。最小 22.2、最大 31.4。対象 id1713 は 29.7KB） |
| 1枚あたりの時間 | **58ms**（v1 34ms） |
| 40枚の合計 | 2.4秒 / 1,154.8KB |
| 48枚に換算 | **2.8秒 / 1,433KB** |

盛ったぶん、1枚あたり大きさが2.6倍、時間が1.7倍になった。それでも48枚で2.8秒。
いまの `daily.sh` は `npm test` だけで約26秒かかるので、1日2回の実行の中では誤差のまま。

- **焼きは v2 でも決定論的**。同じ系統を2回焼くとバイト単位で同じ画像になった（6枚で確認）。
  `feTurbulence` の種も系統の id から決まる。変わっていない系統は git が書き換えを記録しない。
- **1日あたり焼き直す枚数は、いまのところ 0枚**（v1 と同じ。形の時代は1号200万年で、
  生きている40系統の顔ぶれが日ごとに変わらない）。
  `bake.mjs` が出す「1日 2.80MB の書き換え」は全枚数を毎回焼き直した場合の上限で、
  実際の git への書き込みはほぼ発生しない。

→ 判定基準2（48体・1日2回の運用に耐えるか）は v2 でも**耐える**。

### スマホ側の表示コスト

同じスマホ幅（390px、画素密度2）で、48枚並べた状態を比べた。

| | いまの図鑑（SVG） | 焼きカード（WebP） |
|---|---|---|
| DOM の節点 | 2,883（うち SVG 2,555） | **219** |
| 初回描画 | **24ms** | 36ms |
| load | 55ms | **45ms** |
| スクロール中のフレーム | 16.7ms（60fps） | 16.7ms（60fps、最大17.2ms） |
| 転送量 | SVG 207KB（HTML に埋まる） | 画像 約1,433KB（遅延読み込みあり） |

**正直に書くと、焼いても速くはならない。** いまの SVG もすでに60fpsで、初回描画はむしろ
SVG のほうが速い（画像の復号が要らないため）。DOM の節点は13分の1になるが、この規模では
体感差にならない。

焼いて得られるのは速さではなく**密度**。`feTurbulence` や多層のぼかしを48枚ぶんスマホで
毎フレーム動かすのは現実的でないが、焼けば1枚の画像として置くだけで済む。
この試作の価値はそこにある、というのが実測から言えること。

## 目標コンセプト画との比較（2026-11-24 受領）

目標画は Owner から受け取った1枚（顕微鏡で覗いた細胞。紫と青緑の2色、濡れた質感、
分岐する偽足、密な繊毛、多数の細胞小器官、ピント外の土）。**リポジトリには置いていない**
（公開範囲は Owner が決めるため）。比較は受領した画と `sample/cell-1713.webp` を
同じ大きさに並べて行った。

### 判定の前提（Owner 決定、2026-11-24）

- 偽足0本（`asym` が単細胞に出ない）と、縦の占有率約55%（重力1.48倍で平たい）は
  形質の帰結なので未達に数えない。7割の判定は「形質に阻まれていない要素」の中で行う。

### 要素ごと（v2 で再採点）

| 観点 | v1 | **v2** | v2 で何をしたか／まだ何が足りないか |
|---|---|---|---|
| 膜の半透明と層 | 3割 | **7割** | 線を厚みのある帯にし、52〜68本の桟を帯の上に走らせた。内側の境界を2本残して向こう側が透ける。足りないのは帯そのものの奥行きで、目標は帯の中にも層が見える |
| 核の大きさと縞の構造感 | 5割 | **7割** | 縞を円弧にして球に巻きつけ、極に近いほど間隔を詰めた。球の陰影も強めた。足りないのは縞の明暗の振れ幅で、目標はもっと高コントラスト |
| 内部器官の見え方 | 3割 | **7割** | 5個→23個。黄金角のらせんで決定論的に散らし、ミトコンドリアには内部のひだを描いた。アクセント色で地と対比。足りないのは器官どうしの前後関係と、間を埋める細胞質の流れ |
| 繊毛 | 5割 | **7割** | 54→96本。長さ・太さ・明るさをばらつかせた。足りないのは細さで、まだ毛というより棘に近い |
| 光とにじみ | 4割 | **6割** | 屈折のにじみを強め、液胞にハイライト、繊毛の先を明るくした。頭打ちなのは、全面の鏡面を追わないと決めているため |
| 背景のピント外ぼけ | 2割 | **5割** | ぼけた礫26個を奥の層に、粒11個を手前の層に置き、ぼかし量を変えて奥行きを作った。足りないのは接地面と暖色の礫（色は恒星の決まりに縛られる） |
| 全体の色の深さ | 3割 | **6割** | 視野の外周を大きく落として明度の幅を広げ、アクセントの彩度を上げた。頭打ちなのは、2色構成そのものを追わないと決めているため |

**7観点の平均で、およそ 6.4割。合格ライン（6割）を満たす。**

到達可能な天井が約7割（残り3割は「追わないもの」で構成される）という読み替えに照らすと、
埋められる差分はほぼ埋め切った。残っている不足は、どれも「もう一段の描き込み」であって
作り方の問題ではない。

### 差分の分類（v2 時点）

**実装で埋められるもの**（v2 で埋めた）

- 膜を「線」から「帯」へ。縞を帯の上に走らせる ✓
- 核の縞を円弧にして球に巻きつける ✓
- 器官を5個から23個へ。共有部品を黄金角のらせんで決定論的に散らす ✓
- 背景に奥行きの層（奥の礫と手前の粒で、ぼかし量を変える）✓
- 明度と彩度の幅を広げる（色相は恒星の決まりの中）✓

**実装で埋められるが、v2 では手を付けていないもの**

- 器官どうしの前後関係と、細胞質の流れ（目標画の渦）
- 繊毛をさらに細く
- 核の縞のコントラスト

**追わないもの**（確定）

- 濡れた質感と全面の鏡面ハイライト。`docs/art-bible.md` 9「避けるもの: 写実的な質感」に
  正面から反する。Muse も「濡れた質感に寄せると『キモいだけ』に転ぶ」と警告していた
- 紫と青緑の2色そのもの。色は恒星の種類が決める（アートバイブル4）。この惑星は青白い恒星。
  v2 のアクセント色も、恒星のパレットが持つ色相の範囲に収め、対比は彩度と明度で作っている
- 分岐する大きな偽足。形質（`asym`）の帰結として扱う

## v3 全単細胞への横展開（2026-11-24）

v2 の様式を、いま生きている単細胞 **40系統すべて**に当てた。様式は変えていない。
破綻は直さず、分類だけ記録する。

- コンタクトシート: `sample/contact-baked.webp`（焼きカード40枚）と
  `sample/contact-svg.webp`（同じ40系統のいまの図鑑カード）。同じ升目なので並べて比べられる。

### 実枚数での実測（40枚。48枚への換算ではない）

| | |
|---|---|
| 合計 | **2.3秒 / 1,154.8KB** |
| 1枚あたり | 54ms / 29.9KB（中央値。最小 22.2、最大 31.4） |

模様ごとの大きさ: しま 30.0KB（29枚）/ 斑点 27.8KB（6枚）/ 帯 26.3KB（1枚）/ 光る 22.5KB（4枚）。
光るがいちばん小さいのは、膜の桟が描かれていないため（下記の破綻1）。

### この惑星に実在する形質

| | |
|---|---|
| 模様 | しま 29 / 斑点 6 / 光る 4 / 帯 1。**無地は現存しない** |
| 場所 | 陸 28 / 海の浅いところ 12（中ほど・深いは現存しない） |
| 大きさ | 40系統すべて「目に見えない」 |
| drift | −3 が4、−4 が24、−5 が8、−6 が4 |
| asym | 40系統すべて 0 |
| 色相 | 194〜197（ほぼ同一）。明るさ 0.33〜0.53 |

### 破綻の分類

**破綻1: しま以外の模様が、絵のどこにも出ていない（11系統、27%）**

v2 で足した膜の桟と核の弧は、どちらも `pattern === 'stripes'` のときだけ作られる。
斑点6・帯1・光る4 の計11系統は、桟0本・核の弧0本になり、**模様を持つという形質が
絵に反映されていない**。膜は無地の灰色の輪、核は無地の球になる。
v1 には模様ごとの描き分け（斑点・しま・帯）があったので、v2 で様式を入れ替えたときに
しま以外が落ちた。**v2 の様式の取りこぼし**であり、形質側の問題ではない。

**破綻2: 光る系統で、発光が輪郭を食う（4系統、10%）**

発光のにじみが膜の帯と繊毛を覆い、細胞の輪郭が光の塊に溶ける（`sample/contact-baked.webp`
の id2538、id2456 が顕著）。破綻1と重なって、帯に桟も無いため、形が読めない。
「発光が実際に乗っているか」= 乗っている。「盛りすぎていないか」= **盛りすぎ**。
にじみの半径と不透明度が、体の大きさに対して大きすぎる。

**破綻3: drift と内部器官の数の対応が破れている（全系統）**

器官の数・桟の本数・核の弧の数は、いずれも `|drift| % 3` から決めている。このため

| drift | 器官 / 桟 / 核の弧 |
|---|---|
| −3 | 20 / 52 / 9 |
| −4 | 23 / 60 / 11 |
| −5 | 26 / 68 / 13 |
| −6 | **20 / 52 / 9**（−3 と同じ） |

**drift −3 と −6 が同じ姿になり、−6 は −5 より器官が少ない。** 形質としては別物なのに
絵が一致し、並び順も単調でない。剰余で畳んだのが原因。

**破綻4: 金太郎飴に戻ってはいないが、まだ重複が多い**

見た目を決める値（模様・器官数・桟・核の弧・場所・明るさ）の組み合わせは
**40系統で21通り**。最大の群は**10系統が完全に同じ値**で、**63%（25/40）が他の系統と
組み合わせを共有**している。v1 よりは分かれたが、一覧で個体を言い分けられる状態ではない。
ただし原因の大半は形質側（drift が4値しかなく、asym は全0、大きさは全て同じ、色相は194〜197）で、
**様式の問題ではない**。段階2（収斂）の領域。

**破綻ではないもの**

- 色と大きさが「別物に見えすぎる」ことは起きていない。明るさ 0.33〜0.53 の幅は、
  青緑寄りの個体（id2322、id2584 など）として読める程度で、同じ星の生き物に見える。
- 器官の配置は形質と矛盾していない（黄金角のらせんで、核を避けて決定論的に散る）。
  矛盾しているのは数の決め方（破綻3）だけ。

### 直すなら（今回は直さない）

1. 破綻1 — 桟と核の弧を「しまのとき」ではなく「模様の種類ごとの描き分け」にする。
   斑点なら帯に粒、帯なら太い帯、無地なら桟なしで核に陰影だけ、など。
2. 破綻2 — 発光のにじみを体の大きさに比例させ、膜の帯の上には乗せない。
3. 破綻3 — 剰余をやめ、drift を範囲でそのまま写す（単調な対応にする）。
4. 破綻4 — 様式では解けない。段階2で形を担う形質の変異を増やす話。

## 分かった不都合

**いまの決まりでは、単細胞に `asym` は出ない。** 段階1で、左右の非対称と関節の向きの変異を
「体の型ができてから（複雑さ3以上）」に限定したため。条件に合う29系統すべてが `asym: 0` で、
偽足は構造的に生えない。

形質の決まり方は触らない指示なので、実装は仕様どおり `asym` から出すままにしてある。
これは段階2（収斂）が扱う領域への申し送り。単細胞にも形の個性を持たせたいなら、
`lookQuirkChance` の適用条件を見直すことになる。
