# 試作 05: 途中経過（チェックポイント）

## 確かめる問い

試作04のシミュレーションの状態を丸ごと保存し、そこから続きを計算しても、創刊号から計算した歴史とハッシュが一致するか。Node で保存した途中経過をブラウザで読み込んでも一致するか。

## 動かし方

```text
node save.mjs           # 試作04の台帳を創刊号から計算し、50号ごとの途中経過を checkpoints/ に保存する（保存済みは凍結）
node test.mjs           # 途中経過のテスト（約25秒）
node browser-test.mjs   # Chromium で、Node が保存した途中経過から続きを計算して比べる（Playwright が必要）
```

試作04（`../ecosystem-core/`）の `sim.mjs`、`constants.mjs`、`ledger.json`、`history.json` は読むだけで、書き換えない。

## 仕組み

- 途中経過は1つずつファイルにする。名前は計算し終えた号数（`checkpoints/00050.json` など）。間隔は50号（`constants.mjs` の `checkpointEvery`）。中身は状態そのもの（`state`）と、それが何に対して正しいかの見出し。
  - `simVersion`、`rulesHash`: 計算の版と定数。定数を変えると自動で合わなくなる。`sim.mjs` の計算を変えたら `SIM_VERSION` を上げる。
  - `seed`、`count`、`issueNo`、`ledgerHash`: どの惑星の、台帳の何号目までを計算した状態か。凍結済みの号が書き換わっていたら合わない。
  - `snapshotsHash`: それまでの記録（観測データ）のハッシュ。1号ずつ鎖のようにつなぐので、記録が伸びても前の値に足すだけで済む。ブラウザが読む観測データと途中経過が、同じ計算から出たものかを確かめる。
  - `stateHash`: 状態のハッシュ。壊れたファイルや手での書き換えを見つける（改ざん対策ではない）。
- 状態は丸ごと保存する。項目の一覧は持たず、状態 `W` の中身を全部書く（記録 `history` だけは別）。試作04には途中で増える項目（`_superAnn`）もあり、一覧方式だと保存し忘れが起きる。
- 数は JSON の10進表記で、ビット単位まで往復する。往復できない値（-0、NaN、Infinity、undefined、関数、Map、同じ物の共有、配列の穴）が状態に入っていたら、保存の時点で止まる。
- 乱数の状態は保存しない。試作04は号ごとに（種、号番号、digest）から乱数を作り直すので、号をまたぐ乱数の状態がない。号をまたぐ乱数を持たせるときは、`W` に数値で持たせる。
- 読み込みは Fail Closed。見出しが1つでも合わない途中経過は使わず、1つ前の途中経過へ、それもなければ創刊号からの計算へ戻る（`latestUsable`）。
- 保存済みの途中経過は凍結する。同じ形式ときまりのまま中身が変わったら、`save.mjs` は何も書かずに止まる（計算を変えたのに版を上げ忘れた、を見つける）。形式かきまりが変わったときは作り直す。
- Node でもブラウザでも同じ `checkpoint.mjs` を使う（`node:` のモジュールを使わない）。

## 結果

- 実データ238号: 0号目から238号目まで、すべての号で途中経過を保存して読み戻し、最後まで計算した。全史のハッシュ（`808f8d49…`、試作04と同じ）と最後の状態のハッシュが 239/239 で一致。
- 合成の号（8本 x 1500号）: 実データでは起きない状態（全球凍結の最中、全滅のあと、海の蒸発後、洪水玄武岩の最中、系統が上限）を含む737か所で保存して再開し、その先30号の状態が毎号一致。途中から最後まで計算した全史も 8/8 で一致。12,000個の状態のどれにも、保存できない値は出なかった。
- ブラウザ（HeadlessChrome 157）: Node が保存した50、100、150、200号目の途中経過から続きを計算し、全史と最後の状態が Node と一致。計算時間は、創刊号からの238号が約56ms、200号目からの38号が約10ms（このマシンの値）。
- 見る力の確認: 状態を記録と同じ小数4桁に丸めて保存すると、全史が変わる（3/3 で検出）。項目を1つ保存し忘れて初期値に戻すと、14項目中11項目で全史が変わる。変わらなかった3つ（`T`、`dust`、`_superAnn`）は、その号のうちに上書きされるか、すぐ消える値。
- 気づいたこと:
  - このシミュレーションは小さなずれを吸収する。連続な値を最小単位（1 ulp）ずらすと、最後の状態は12項目中7項目で変わるが、記録（小数4桁）は1つも変わらなかった。決定論のテストは、記録より状態のハッシュで比べるほうが鋭い。
  - 作業中に途中経過の形式（観測データのハッシュの作り方）を変えたとき、`save.mjs` が古いファイルとの食い違いを見つけて止まった。凍結の仕組みが実際に働いた。
  - 途中経過1つは約0.6〜9.8KB（系統の数で変わる）。50号ごとなら1年（約730号）で15個、約150KB。
- 2026-11-19: 本番の `engine/checkpoint.mjs` と `engine/observations.mjs` として書き直した（観測データのまとまりと manifest を足した）。
