# 試作 07: 生き物の視点

## 確かめる問い

同じ場所に別の体で降りると、別の世界に見えるか。

これはこの作品の賭けの部分。神の視点はシムシティの文法を借りられるが、「目のない種は
点群と音の波紋で世界を知る」はこのゲームにしかない。ここが成立しなければ、柱2（二つの
視点でたどり直す）の片側が立たない。

## 動かし方

```text
python3 -m http.server 8000   # リポジトリのルートで
# http://localhost:8000/prototypes/creature-view/
```

本番の `engine/`、`viewer/plan.mjs`、`viewer/draw.mjs`、`viewer/palette.mjs` を読むだけで、
書き換えない。公開データ（`data/`）から図鑑と同じ世界を組み立て、放射腕で触手を持つ系統を
判定の対象にする。

three.js は `0.187.0`（r187）を importmap で固定し、jsdelivr から読む（MIT。調査ログ
`_ai-logs/2026-11-05_times-garden-rendering-research.md` の「3D は必要になった時点で
three.js r187」に従う）。ネットワークから CDN に届かない環境では、`three` の解決先を
手元の `node_modules/three/build/three.module.js` に差し替えて動かす。

## 仕組み

- `body3d.mjs`: 本番の `viewer/plan.mjs` が作る体の設計図を three.js のメッシュにする。
  形質の解釈はしない。SVG の図鑑（`viewer/draw.mjs`）と同じ設計図を読むので、カードの姿と
  3Dの姿が同じ系統になる。設計図は平面なので、奥行きだけはここで一度決める。
  - `ellipsoid` → つぶした球 / `spike` → 先細りの円錐 / `loop` → 押し出して角を丸めた塊
  - `dome` → つぶした半球 / `strand` → 点の列に沿った管（先へ行くほど細い） / `membrane` → 薄い膜
  - 目は、いちばん大きな塊の表面に置く
- `view.mjs`: 地表、同じ系統と別の系統を数体、恒星の色の光。見え方を3つ切り替える。
  - レンズの目: ふつうの見え方。ローポリでマットな質感
  - 目のない種: 走査（赤外線）が通った点が光って消え、音の波紋が通った点が一瞬強く光る。
    点群は1つの ShaderMaterial で描き、走査角と波紋の半径だけを毎フレーム渡す
  - 姿を見る: 1体をゆっくり回して、図鑑のカードの絵と見比べる
- 画素密度は最大2。フレームが重い状態が続いたら描画倍率を下げる。dt の上限は250ms。

## 結果（途中まで。実機は未確認）

- 設計図を共有する方式は成立した。カードの絵と3Dの姿が、腕の本数も触手の本数も同じになる。
- 目のない種の見え方は、意図した絵になった。放射腕と8本の触手が点の輪郭として読め、
  同じ種とわかるのに、レンズの目とはまったく違う世界に見える。
- コンテナの Chromium（swiftshader、スマホ幅390px、画素密度2）で3つの見え方を撮影し、
  コンソールのエラーなし。
- 未確認: 実機のスマホでの手触りと速さ。swiftshader はソフトウェア描画なので、速さの
  判断材料にならない。
- 残っている粗さ: うろこなどの体の覆いが3Dに出ていない。球の面の割りが目立つ。地表が
  のっぺりしている。音の波紋が、走査と見分けづらい。
