# 試作 09: キャラ化縦切り

## 確かめる問い

生き物をスマホゲーム級のキャラに立たせるのに足りないのは、解像度や描き込みではなく
**キャラ設計の層**か。

段階4（`eco-4`）の図鑑の「文明」節が Owner 判定で不合格だった。都市が「四角いビル＋窓の点々」
という人間の都市の記号でしかなく、住んでいる生き物の体がどこにも出ていない。
Owner の仮説は「描き込みが足りないのではなく、下の4点を決める層が無い」。これを試す。

判定基準（Owner が判定する）:

1. シルエットだけで種が言い分けられるか
2. 焦点（目・核・発光など視線の置き場）が1つ決まっているか
3. 比率とポーズに、その種らしさ・性格が形質の範囲で出るか
4. 陰影の様式（2〜3段のセル陰影＋縁の光＋接地影）が体の型をまたいで統一できるか

## 置き場と役割

- `rig.mjs`: **キャラ層のデータ**。体の型ごとに、比率・焦点・ポーズ・陰影・接地影を数で持つ。描かない。
- `char.mjs`: rig と体の設計図（`viewer/plan.mjs`）から1体を SVG にする。設計図の読み方は
  `viewer/draw.mjs` と同じで、形質の解釈はしない。
- `scene.mjs`: 文明シーンの方向性サンプル1枚（#314・崖の住まい・町）。
- `bake.mjs`: 焼き（Chromium の canvas で WebP）。本番の `data/cards/` には書かない。
- `compare.html`: 旧（いまの本番）と新（キャラ層）の比べ。シルエット切替と形質→絵の対応表つき。
- `subjects.json`: 対象3系統の実値。`sample/`: 焼いた結果の保存版。`out/`: 焼きの出力先（git に入れない）。

守ったこと:

- `viewer/plan.mjs` の「形質 → 形の設計図」の決定は1つも変えていない。腕の本数は drift、先の形は
  joint、左右の非対称は asym、目の数と位置も plan のまま。rig が決めるのは見せ方（倍率、回転、陰影）だけ。
- `engine/` には触っていない。歴史は1ビットも動かない。
- 本番（`viewer/`、`pipeline/`、`index.html`）への組み込みはしていない。

## rig の表

| 体の型 | 比率（デフォルメ） | 焦点 | ポーズ | 陰影 | 接地影 |
|---|---|---|---|---|---|
| 体節型 | 先頭の節 x1.42、後ろへ x0.86 で細く、目 x2.4、翼を26度持ち上げ | 目 → 発光 → 芯 | 前傾の構え（傾き -6度、振り 14度） | 3段 + 縁の光 2.3 | 接地（広がり x1.12、濃さ 0.45） |
| 放射腕 | 中心 x0.86、腕 x1.24、目 x2.2 | 目 → 発光 → 芯 | 面に貼りつく（-9度、振り 10度） | 3段 + 縁の光 2.1 | 浮遊（x1.3、0.3） |
| 傘型 | 傘を横に x1.14、触手 x1.3、目 x2.2 | 発光 → 目 → 芯 | 開いた瞬間（-3度、振り 16度） | 2段 + 縁の光 2.6 | 浮遊（x1.1、0.24） |
| 胞子型 | 本体 x0.94、棘 x1.1、目 x2 | 発光 → 目 → 芯 | 静止（4度、振り 6度） | 2段 + 縁の光 2 | 接地（x0.8、0.5） |
| 不定形 | 核まわり x1.18、目 x2.2 | 核 → 発光 → 目 → 芯 | たゆたう（-4度、振り 8度） | 2段 + 縁の光 2.4 | 浮遊（x0.9、0.26） |

ポーズは形質で振れる（傾き = 型の基本 + 関節の向き x2.2 + 非対称なら +3度）。
焦点は「その種が持っているもの」からしか選ばない。目のない系統に目や顔は足さない（id 1713 は核が焦点）。

様式の作り:

- **シルエット**: 触手も脚も線ではなく先細りの帯（塗る形）にして、輪郭に出るようにした。
- **陰影**: シルエットで切り抜いた中に、固有色 → 影（光の反対側に置いた大きな円）→ 光（3段のときだけ）。
- **輪郭**: 塗りの下に太い線を敷いて外の縁だけを残し、節の境目は薄く重ねる（1つの塊に見せる）。
- **縁の光**: 同じ形を白で塗り、光と反対へずらした同じ形を黒で塗るマスクで、外の縁の光の当たる側だけ。
- **接地影**: 接地する種は体の底を地面の線に合わせて濃く小さく、浮く種は広く薄くずらす。

## 解けなかった点

- **単細胞（id 1713）は、新しい様式のほうが良いとは言い切れない**。核が焦点として立つのと、
  縁の光と接地（浮遊）影が付いたのは効いているが、試作08 v2 の密度と色の豊かさは、
  セル陰影を重ねたぶんだけ落ちている。細胞は「キャラ」より「顕微鏡の標本」なので、
  この層が要るかどうかは Owner の判定を仰ぐ。
- **体節型の2つ目の目が、3節目に乗る**。目の位置は `viewer/plan.mjs` が体の幅いっぱいに散らす
  決まりで、体節型だと頭から外れる。キャラとしては頭に寄せたいが、これは「形質 → 設計図」の
  決定なので、この試作では上書きしていない（本番側か段階2の判断）。
- **文明シーンは1枚だけの方向性サンプル**。段階×住まいの全組み合わせには広げていない。
  崖の段・入口・止まり場の寸法は #314 の体の幅から決め打ちしてあり、他の型には合わない。
- 旧様式との比較は「同じ寸法で並べる」までで、どちらが良いかの判定はしていない。

## Owner の判断が要る点

1. 4つの基準の判定（進める / 方向転換 / やめる / 未判定）。
2. 単細胞にこの層を通すかどうか（上の「解けなかった点」の1つ目）。
3. 体節型の目の位置を `plan.mjs` 側で変えるかどうか（変えると図鑑の絵が変わる。歴史は変わらない）。
4. 文明シーンの方向（崖の穴・止まり場・痕跡の密度）で進めてよいか。進めるなら、段階×住まいの
   全組み合わせをどう作るか（型ごとに住まいの寸法を決める層が要る）。
5. 図鑑カードの `#1216 から・70号` という書き方が、系統の id と読み違えられた。
   `#1216 の号から` のような書き方に直すか（本番の `viewer/bestiary.mjs` の1行）。
